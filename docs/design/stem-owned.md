# 独占枝轴：每个节点自己的笔直树干

- 日期：2026-10-17
- 状态：用户提出结构修正后的实验设计；只验证骨架，不宣布最终树形。
- 结果：[单例报告](../experiments/stem.md)。

## 1. 修正的问题

旧 C/S 模型把子节点放在父节点的射线上。单子节点会直接继承父轴，奇数分叉的中间子节点也会与父轴共线，于是父节点上方立刻被某个子节点占据，父节点没有属于自己、向上冒出的树干。

用户要求：

1. 每个节点独占一段笔直的枝轴，并向上冒尖。
2. 子节点从父枝轴上的分叉点长出，而不是从父节点框的中心继续延伸。
3. 没有任何子节点延续父枝轴的方向；单子节点也必须偏向一侧。
4. 子树枝轴保持笔直，可为倾斜；子树按相同规则递归，不要求垂直。

## 2. 几何模型

每个节点 `N`：

- 在父枝轴上有一个分叉点 `F`（根没有分叉，枝轴从根框开始）。
- 枝轴是从 `F` 穿过 `N` 的相框中心、继续延伸到自由末端 `T` 的一条直线。
- `N` 下方到 `F` 的部分是接入枝；`N` 上方到 `T` 的部分是 `N` 独占、冒尖的枝轴。
- 所有直接子节点的分叉点都在 `N` 枝轴上、`N` 相框之上。子节点先按子树规模降序处理（输入顺序仅破平局）；碰撞搜索可能让后处理的轻枝落在更低位置，不保证分叉高度单调。
- `N` 的枝轴末端必须高于最后一个分叉点至少 `tip = 44`；保留原扫描在实际抬高分叉后额外留一个 step 的余量。

子节点 `C`：

- 首选侧按**已实际安放的子树规模**决定：重枝先处理，输入顺序破平局，优先选择累计负载较轻侧。首选侧全部候选失败后允许[有限换侧](side-search.md)，因此人数配平是偏好，不是硬约束。
- 方向 = 父枝轴方向 `+ δ`，`δ = ±32°`，符号来自上述侧别。恰有一个子节点时 `δ = 0`（延续父轴，2026-10-20 修订），其余情况绝不为零。
- 若该方向会让子枝轴的绝对倾角超过 `maxAngle = 70°`，则翻到另一侧；仍越界就报错，不生成向下生长的树。70° 足够让父枝已倾斜 32° 时，两个等量子节点仍能各占一侧（64° 与 0°）。
- 负荷相等时优先选让绝对倾角更接近垂直的一侧；两侧绝对角相等时按深度交替。这样单子链会回弯到 0°，不会逐级漂到轴另一侧。
- 相框中心位于接入枝上；优先使用 `connect = 80`，完整几何搜索失败后才尝试更长接入，详见[几何避让设计](geometry-clearance.md)。相框仍水平、不随枝条旋转。
- 其自身枝轴继续沿 `δ` 方向延伸，并按同样规则接纳自己的子节点；子树在旋转后的局部坐标中构建，因此枝轴笔直但可倾斜。

分叉高度从 `相框高度 + 间距` 起按 `step = 6` 递增，完整判定装配几何，失败后尝试有限接入长度；首选侧全部失败时，若角度合法且全树共享预算仍有余量，再尝试另一侧。新绝对方向下重新构建子树，成功才更新侧负荷；两侧仍失败则显式拒绝。不回溯已接受兄弟。

## 3. 旋转后的间距

相框保持水平，枝条旋转，因此“在局部坐标里满足 12 单位轴向间距”不能保证旋转后仍满足；首轮实验确实出现旋转后最小轴向间距降到 3.79。修正为旋转不变的门槛：

`minCenter = hypot(width + gap, height + gap)`。

若任意两框中心距离达到 `minCenter`，则在任意旋转下，两框至少在一个坐标轴方向相隔 `gap`。放置时逐对检查人物中心距离，不再使用局部轴对齐包围盒。该门槛比单个方向上的 12 单位更保守，实测最小轴向间距为 23.9，但这是有意的正确性代价。

框—框之外，使用相框外接圆及枝带胶囊进行旋转不变的保守碰撞检查；包括祖先枝、后代框及父轴延长，合法分叉的连接重叠除外。成功场景必须通过最终完整判定；见[本轮结果](../experiments/clearance.md)。

## 4. 必须成立的结构不变量

- 每个节点恰有一条枝轴；枝轴从分叉点（根从框中心）开始，长度大于相框到末端的距离。
- 非根节点的方向与父枝轴方向之差在有多兄弟时为 32°，独子时为 0（且子枝起点恰在父枝终点）。
- 每条枝轴的绝对倾角不超过 70°，保证子节点始终高于父节点。
- 子分叉点位于父枝轴的线段上，且严格低于父枝轴末端。
- 子相框中心与父枝轴的垂直距离至少为 `相框宽度/2 + 间距`，父枝轴不被子框覆盖。
- 父枝轴末端与最高分叉点的距离至少为 44，实际抬高后的扫描余量保留。
- 根枝轴垂直；更深的子树枝轴只要笔直，方向不限。
- 同一输入确定，输入不被修改，所有人物向上生长。

## 5. 实现与边界

- `src/layout/` 按阶段拆分：`side.ts`（分侧）、`order.ts`（排序）、`spacing.ts`（分叉间距）、`connection.ts`（接入长度）、`crown.ts`（树冠高度）、`centroid.ts`（重心度量），`index.ts` 只负责递归与装配；契约与回退边见[布局阶段拆分](layout-stages.md)。
- `src/generate-one-subtree.ts` 只调用 `run()`；输入树来自 `config.json` 指向的 `data/one-subtree.json`，输出路径与标题也来自配置。
- `tests/` 存放全部断言、独立复查、固定输入与实验入口；`src/` 不 import `tests/`。
- 只做了骨架与间距。枝轴美学、树皮纹理、叶、相框挂接、标签避让未实现。
- 固定 32°、70° 上限、44、6 与基础接入 80 是可解释参数，不声称最优；B 仅在需要时延长接入。
- 已验证多层满二叉树、链、扇与多个展开子树；有限候选搜索不保证任意树成功，不是生产 API。64° 父枝的两子同侧问题仍存在。
- 当前默认（有限换侧 + 祖先轴走廊预留）在固定 200 个随机输入上全部出图（200 / 0），9 节点父轴受阻反例已解决；代价是画布约 +15%，见[验收指标](acceptance-metrics.md#4-重新冻结祖先轴走廊预留2026-10-20)与[侧别结果](../experiments/side-search.md#2026-10-20-更新9-节点反例已解决)。

### 输入、布局与渲染数据契约

本轮按用户要求迁移为 TypeScript + Zod，拆分职责，不新增响应式框架：

- `config.json` 是全部布局、宽度、画布、文字与输出路径参数的持久化来源；`src/config.ts` 负责 Zod 校验、角度换算与基于配置文件目录的路径解析。配置不静默合并，缺失或拼错字段报错。
- `src/parse.ts` 只将 JSON/YAML 文本变成未知对象；`src/validate-tree.ts` 再检查根数量、环、共享子节点、重复 ID 和节点字段。支持单根对象或仅含一个根的数组；零根或多根显式拒绝，不丢弃额外树。
- `src/data.ts` 是 Zod schema 与 `z.infer` 类型入口。`TreeNode` 仍只描述关系；`RenderTree` 用 `phase` 区分 `initialized` 与 `laid-out`，人物通过 `parentId/children` 的 ID 引用组成规范化树。
- `src/state.ts` 初始化人物身份、人数、宽度和配置快照，`geometry=null`，不伪造坐标。布局结果通过 `applyLayout` 按 ID 全量应用，校验重复、缺失、未知 ID 与非有限坐标；返回新快照，不修改初始化状态。
- `layoutStemScene(initialized, layoutConfig)` 是纯空间计算，接收完整配置，不读文件、不生成 SVG，不计算显示样式；只返回每个人的 `{id,center,from,to,angle}`。现有有限侧别/长度/高度搜索及失败边界不变。
- 渲染器只接收 `laid-out` 状态，拒绝 `geometry=null`，按状态中的坐标、全宽、框尺寸和渲染参数绘图。坐标 y 向上，只有渲染器翻转 SVG 坐标；节点次序保留布局的绘制顺序。
- 主流程先读取配置，再依次解析、校验、初始化、计算、应用、渲染，最后才写输出。入口文件仅调用主流程；任何前置阶段失败不得覆盖已有结果。
- 源码与测试统一为 `.ts`，不保留 `.mjs` 入口或 JSDoc 类型副本；严格 TypeScript 检查负责静态契约，Zod 负责文件输入与配置的运行时校验。

验收：JSON/YAML 等价输入、语法/结构/配置失败、初始化状态禁止渲染、布局纯函数与不可变应用、配置跨工作目录读取和文件到 SVG 全流程；原六节点/A-B/冻结 200 树摘要不漂移。

## 6. 验收

1. 结构不变量由 `tests/stem.test.ts` 逐项断言；`bun run test` 覆盖解析、配置、状态、布局、几何与渲染。
2. `bun run generate` 生成六节点基线；`bun run typecheck` 检查类型；`bun run experiments` 重现 A/B 与冻结 200 树，二者摘要均不得漂移。
3. 浏览器打开生成的 SVG，确认没有任何节点直接位于父节点正上方，且每个父枝轴都越过自己的最高分叉。
4. 失败与空间代价写入结果；不以缩略图或叶片掩盖。
