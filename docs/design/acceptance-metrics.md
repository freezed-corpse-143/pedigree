# 验收指标（冻结）

- 日期：2026-10-20
- 状态：已冻结。任何布局改动必须先跑 `bun run metrics`，四项形状指标与两项预算不得越过下表门槛。
- 实现：`tests/metrics.ts`（计算、写 `output/metrics/metrics.json`、断言门槛）。
- 背景：`docs/design/layout-stages.md` 记录的下一步（D3 间距、C3 重心）都会改变布局结果，先冻结“什么算退步”。

## 1. 指标与门槛

| 指标 | 定义 | 当前值 | 门槛 | 为什么这样定 |
|---|---|---|---|---|
| M1 接受数 | 200 棵冻结语料中成功出图的棵数 | **200** | `≥ 200` | 完整性是需求里的硬约束，见 §4 的重新冻结 |
| M2 拒绝数 | 显式 `STEM_NO_PLACEMENT` 棵数 | **0** | `≤ 0` | 与 M1 同源 |
| M3 树冠比例 | `height / width`（含相框留白） | p50 1.572 · p95 2.208 · max 2.673 | p50 ≤ 1.6 · p95 ≤ 2.25 · max ≤ 2.7 | 直接对应“不能矮胖” |
| M4 分叉平衡 | 对每个 ≥2 子节点的父节点，子节点相对父中心的 `|Σx| / Σ|x|`，再取平均 | p50 0.513 · p95 0.845 · max 1.000 | p95 ≤ 0.9 | 平均而非逐点，避免单棵极端值卡死合法树 |
| M5 画布宽度 | 包围盒宽度 | p50 447.5 · max 805.2 | p50 ≤ 460 · max ≤ 820 | 防止用放大画布换形状 |
| M6 画布高度 | 包围盒高度 | p50 704.6 · p95 1037.3 · max 1396.7 | p50 ≤ 720 · max ≤ 1420 | 同上 |
| M7 基础接入占比 | 接入长度等于 `connect` 的节点比例 | mean 0.911 | `≥ 0.89` | 允许为走廊预留加长接入，但不允许无限放大 |
| M8 基线形状 | 六节点图的 `nodes/aspect/axisMoment/branchMoment` | 6 / 1.269 / 0.503 / 0.667 | 四项精确相等 | 基线同时由 SVG 摘要与形状双重冻结 |
| M9 搜索代价（诊断） | 门禁调用次数 / 预算跳过步数 | 13 705 / 2 037（200 棵合计），中位 48 次/棵 | 不设门槛 | 用来确认预算真的生效，而不是死代码 |

`axisMoment`（全体人物横向一阶矩）**不作为门槛**：链式树天然等于 1，用它卡会产生假失败。它只作为诊断值输出（p50 0.623）。M4 只看分叉节点，才是有意义的平衡信号。

## 2. 使用方式

```sh
bun run metrics     # 计算、写 output/metrics/、断言门槛
bun run test        # 阶段与流程断言
bun run experiments # A/B、冻结语料、fork-gap 扫描
```

顺序约定：先 `metrics` 拿现状，再改算法，再 `metrics` + `experiments` 对比。指标失败时**不得**直接放宽门槛；先判断是形状退步还是门槛本身需要重新冻结（后者必须同时更新本文档与 `../CHANGELOG.md`）。

## 3. 已用这套指标否决的方案：固定最小分叉间距

假设：给同一父节点上的连续分叉加一个最小轴向间距，可让子树不挤、树冠更匀。

实现：`layout.minForkGap`（默认 0 = 关闭），在 `spacing.forkFloor` 中把扫描起点抬到 `max(首叉高, 上次分叉 + gap)`。

| gap | 接受 | aspect p50 | aspect p95 | width p50 | width max | 基础接入占比 |
|---|---|---|---|---|---|---|
| 0 | 160 | 1.568 | 2.245 | 388.7 | 767.5 | 0.993 |
| 6 | 150 | 1.555 | 2.228 | 376.0 | 775.3 | 0.991 |
| 12 | 150 | 1.553 | 2.211 | 379.1 | 778.5 | 0.996 |
| 24 | 150 | 1.546 | 2.178 | 385.5 | 791.2 | 0.996 |

结论：**净负收益**。形状只改善 1.4%，却固定损失 10 棵树（M1 直接跌破门槛），画布最宽处反而变大。原因是间距被抬高后，父轴变长、后续子树可用空间变小。

决定：`minForkGap` 保留为可配置参数但默认 0；不把它当作 D3 的实现方向。真正的 D3 缺口是“按子树占用预算分配”，不是“加一个固定缝”。

## 4. 重新冻结：祖先轴走廊预留（2026-10-20）

D3 的第二形态（`reserveAncestorCorridor`）在附着时要求候选子树的所有框都不进入父轴走廊（`frame.width/2 + gap`）。它修好了此前所有 `branch-frame` 拒绝：9 节点反例与 `mixed` 族都能出图。

| 指标 | 走廊关闭（旧默认） | 走廊开启（新默认） | 变化 |
|---|---|---|---|
| M1 接受 / M2 拒绝 | 160 / 40 | **200 / 0** | +40 棵可画 |
| M3 aspect p50 / p95 | 1.568 / 2.245 | 1.572 / 2.208 | 基本不变，p95 更好 |
| M5 width p50 / max | 388.7 / 767.5 | 447.5 / 805.2 | +15% / +5% |
| M6 height p50 / p95 | 640.6 / 931.9 | 704.6 / 1037.3 | +10% / +11% |
| M7 基础接入 | 0.993 | 0.911 | 9% 的枝加长了接入 |
| M9 门禁调用 | 31 123 | 13 705 | 预算更常命中，搜索更省 |

重新冻结理由：需求把“关系完整、可读”列为硬约束，把“紧凑”列为软目标；此时用 15% 画布换 40 棵树完整可用是正确的方向。因此 M1/M2/M5/M6/M7 按新基线更新，并在 `tests/metrics.ts` 中写死新值。

历史复现契约：`clearance-experiment`、`side-search-experiment` 的 A/B 复现显式传 `reserveAncestorCorridor: false`，与 `maxSideTrials: 0` 同等对待，否则会改写已存档证据。

## 5. 冻结后仍允许的变化

- 新增不影响布局的模块、测试、文档：自由。
- 布局改动：必须 M1–M8 全过；若形状指标改善但 M1 下降，视为退步。
- 重新冻结：需要同时给出理由、旧值与新值，并更新本文档、`tests/metrics.ts` 的 `THRESHOLDS` 与 `../CHANGELOG.md`。

### 渲染层不变量（几何指标之外）

指标表只覆盖坐标，不覆盖“画出来能不能读”。以下三项是渲染层断言，改 `src/render.ts` 时必须同时满足（`tests/render-scene.test.ts`）：

| 项 | 断言 | 为什么 |
|---|---|---|
| 自包含配色 | 不含 `fill="var(...)"`；根节点带 `color="#111"`；每个框有 `fill="#fff"` | `var()` 在表现属性里无效，裸栅格器会把框涂黑、文字同色不可见 |
| 标签适配 | 估算宽度超过框内宽时输出 `textLength` 与 `lengthAdjust` | 长姓名不越框；短标签不受影响 |
| 分叉盖缝 | 非根枝从分叉点沿自身方向后退半个起始宽度 | 父枝的平头端盖不再露成缺口 |

形状指标（M3–M8）只依赖坐标，渲染改动不改变它们；六节点摘要与语料哈希在渲染改动后按流程重新冻结，旧值保留在 `baselineSha256History` / `svgSha256V1`。

## 6. 重新冻结：独子延续父轴（2026-10-20）

用户判定：根本只有一个子节点时按自然树常识应当共线。规则改动见 [ADR 0002 修订](../decisions/0002-owned-stems.md#修订-2026-10-20独子延续父轴)。

| 指标 | 旧冻结 | 新值 | 判定 |
|---|---|---|---|
| branchMoment p50 / p95 | 0.513 / 0.845 | 0.533 / 0.778 | 组合分叉更平（p95 变好） |
| axisMoment p50 / p95 | 0.513 / — | 0.344 / 0.948 | 主干不再逐层漂移 |
| 基础接入占比 | 0.911 | 0.961 | 更少拉长接入 |
| aspect p50 | 1.572 | 1.377 | 更紧凑 |
| aspect p95 / max | 2.208 / 2.673 | 3.365 / 7.552 | **变差**：直链条不再靠左右折射扩宽 |
| width p50 / max | 447.5 / 805.2 | 486.2 / 975.6 | 变宽：单侧子树全部落在同一侧 |
| height max | 1396.7 | 1499.1 | 更高：垂直链每层 80 |
| 接受 / 拒绝 | 200 / 0 | 200 / 0 | 不变 |
| 门禁调用 | 13 705 | 11 982 | 更少（延续段无侧别搜索） |

新门槛：aspect p95 ≤ 3.4、max ≤ 7.6、width p50 ≤ 490、max ≤ 980、height max ≤ 1500；其余不变。

**已知根因（下一步）**：相框间距用旋转不变的圆距 `hypot(w+gap, h+gap) = 80.2`，但相框是轴对齐矩形，垂直堆叠只需 `h+gap = 54`。这条保守门禁让每条垂直链多花 26 单位/层，是 aspect 与 height 变差的主要来源。改成矩形间距属独立改动，需单独测量并再次冻结。

## 7. 重新冻结：裸主干占 40%（2026-10-20）

用户反馈：主树干偏低，树冠占树干比例过大，且超参数应改为比例。新增 `layout.trunkShare = 0.4`（固定点迭代实现见 [layout-stages](layout-stages.md#裸主干比例trunkshare)）。

| 指标 | 改前 | 改后 | 说明 |
|---|---|---|---|
| 基线六节点 高 / aspect | 436.6 / 1.269 | 517.9 / **1.505** | 主干抬到 40% |
| aspect p50 / p95 / max | 1.377 / 3.365 / 7.552 | 1.833 / 3.439 / 10.35 | 每条树都更高 |
| height p50 / max | 665.4 / 1499.1 | 895.4 / 2270.6 | +34% / +51% |
| width p50 / max | 486.2 / 975.6 | 486.2 / 975.6 | 不变：只加高，不加宽 |
| axisMoment / branchMoment p50 | 0.344 / 0.533 | 0.344 / 0.533 | 不变 |
| 基础接入占比 | 0.961 | 0.961 | 不变 |
| 门禁调用 | 11 982 | 12 822 | 固定点让搜索起点更高 |
| 接受 / 拒绝 | 200 / 0 | 200 / 0 | 不变 |

新门槛：aspect p50 ≤ 1.9、p95 ≤ 3.5、max ≤ 10.4、height p50 ≤ 900、max ≤ 2280，基线 aspect 1.505。主干比例是**可调视觉参数**，不是算法结论；改它必须同时重跑本表。

## 6. 未纳入

- 视觉美学（枝轴曲率、挂接框、叶片）暂无量纲指标，S4–S5 开始时再定义。
- 交叉数：当前门禁保证零交叉，无需额外指标。
- 运行时间：搜索是有界的有限扫描，未设时间门槛；等 D3 改结构后再测。
